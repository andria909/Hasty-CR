# Пушка с духом и заклинаниями против шара

**В ограниченном поиске найдены оплаченные планы защиты без урона при
потере обеих башен принцесс:** пушка + электродух + Zap за6 эликсира и
пушка + Fireball за7. Это пока планы в симуляторе, не навык обученной модели.

2320 попыток в16 контекстах: четыре состояния вражеских башен, две линии,
задержки1350/2025мс. Свои башни принцесс уничтожены, король активен и с полными
HP. Шар выставлен за5 эликсира с края; решение о пушке принимается через1,5с.
Сначала проверены все36 центральных клеток, затем помощники для двух лучших
одиночных пушек. Позиция заклинания определяется по наблюдаемому положению
противника и одному из трёх смещений; будущие координаты не подаются.

| Лучший найденный план каждого типа | Стоимость | Защита без урона /16 | Средний урон королю |
|---|---:|---:|---:|
| Без карты | 0 | 0 | 3200 |
| Пушка | 3 | 0 | 1280 |
| Пушка + электродух | 4 | 0 | 640 |
| Пушка + Zap | 5 | 0 | 640 |
| Пушка + электродух + Zap | 6 | 16 | 0 |
| Пушка + Fireball | 7 | 16 | 0 |

Это **выбор плана задним числом**, не винрейт модели. Рука фиксирована:
пушка/дух/Zap/Fireball, начальный запас10 эликсира. Команды резервируют и
платят свою стоимость, учитывают занятые слоты и задержку. Противник не
добавляет поддержку и заклинания. Все48 зеркальных сравнений лучших планов
совпали по урону, расходу эликсира, оставшимся врагам и выживанию короля.

Нулевой результат пары с духом не доказывает, что такая защита невозможна:
проверены только две лучшие **одиночные** позиции пушки и ограниченные
позиции/времена помощника. В обычной ситуации живые башни принцесс также
меняют исход. Эти16 контекстов сильно коррелируют, не являются независимым
тестом и недостаточны для отдельного обучения или продвижения модели.

## Исправление генератора учебных последовательностей

Убрана оставшаяся блокировка слота2100мс из поиска, воспроизведения примеров
и проверки политики. Поиск теперь применяет ту же центральную маску,
что PPO; раньше он мог предлагать пушку вне разрешённой области. Добавлена
третья оплаченная команда для проверки сочетаний из трёх карт.

Контракт `sequence_execution.py` включён в контрольные суммы данных.
Генератор требует явного совпадения контракта; старые данные нужно
пересоздавать, а не объявлять актуальными. Уже отправленные GPU-пакеты
сохранены.15 тестов пройдены, включая повторное использование того же слота
через150мс после исполнения, резервирование трёх карт и отказ вне центра.

Новые массивы BC и новое обучение из найденных16 случаев не запускались.
Для использования нужны разнообразные руки/запасы эликсира, время реакции,
положения атакующего и отдельные seed для проверки переноса навыка.
