# Точный вход политики в реальном бою

Добавлен опциональный `--capture-every N --capture-limit 2000` в `scripts/gamestate/memory_play.py`. По умолчанию отключён; текущие веса и правила принятия решений не меняются. В текущей серии запись не включалась.

`decisions/*.npz` содержит planes, уже дополненные joint-признаками scalars, окончательную action_mask после pending/cooldown и решение сети. JSON metadata содержит match/tick, SHA весов, руку, зарезервированный эликсир, занятые слоты и геометрию. Загружать через `numpy.load(..., allow_pickle=False)`.

Сохраняются и WAIT, и выставления: первая и затем каждая N-я оценка сети. Заблокированный до inference вход не записывается. Решение сети не означает успешное выставление: для этого нужен отдельный PLAY/ACK по матчу и тику.

Массивы копируются до следующего решения; сжатие и диск работают в отдельном потоке. Очередь ограничена четырьмя снимками, переполнение пропускает образец; лимит по умолчанию2000, максимум10000. summary.json показывает seen/accepted/written/dropped/error. Ошибка диска прекращает запись, но не выбор действий. Копирование и постановка в очередь всё же имеют небольшую стоимость; её влияние на live-задержку ещё не измерялось.

Проверено37 тестами: совпадение действий с записью/без, точные309 скаляров и маскаWAIT, сохранение данных после изменения исходного массива, лимит и ошибка записи без перезаписи старого файла. Это техническая проверка; новых диагностических live-данных пока нет.

## Воспроизведение

```
.venv-live/bin/python -m scripts.gamestate.replay_decisions \
  --checkpoint /path/to/model.pt --captures /path/to/decisions \
  --output /path/to/new-report.json
```

По умолчанию SHA весов должен совпадать с записью; `--compare` явно разрешает другой чекпоинт при той же геометрии и размерности входа. Проверяются типы, формы, конечность входов, непустая маска и легальность записанного действия. Ни ADB, ни новые матчи не используются. Выход: совпадения действий, отличие value и пять лучших доступных действий. Совпадение действий не доказывает их полезность.

Проверено на настоящих весах BC800 и Cannon/spells: по10 кадров, всего20/20 точных совпадений действий и нулевое отличие value после сохранения/загрузки. Это **новый offline inference** на повторно закодированных старых кадрах, без исторического pending-состояния; не воспроизведение исходных live-решений. [Результат](defense_plan/decision_capture_roundtrip_20261028.json). Ещё3 теста проверяют реальную сеть, несоответствие SHA и нелегальное записанное действие; целевой набор21 тест прошёл.
