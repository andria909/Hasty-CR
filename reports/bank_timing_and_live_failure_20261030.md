## После сбора

1. Перепроиграть безопасные последовательности через фактический observation/mask среды. Не размечать промежуточный WAIT только по безопасному финалу: исключить более дешёвую/эффективную немедленную защиту и проверить запас на следующую угрозу.
2. Добавить контрпримеры: ждать уже поздно; ожидание с полным банком теряет регенерацию; пустой Fireball хуже сохранённого ресурса; требуется немедленная защита. В сценариях накопления учитывать второй оплаченный пуш: один изолированный шар не учит всему управлению банком.
3. Перестановки руки и разделение целых seed до обучения. Оценивать отдельно безопасный WAIT, срочную защиту, пустые спеллы, время ниже4/выше9 эликсира и потерянную регенерацию; дополнительно полные attack/defense validation и семейства.
4. Только после проверки учителя — короткие парные BC/PPO-прогоны с контролем и разными долями WAIT/удержания навыка. Лучшие2–4 продолжаем на полном бюджете, если нет проваленного семейства. Не усиливать награду за пассивность вслепую: предыдущие24 опыта такой подход не исправил.

Нового обучения модели на этих примерах пока нет. Реальные игры не запускаются; v25 сохранена.

## Следующий этап 30 октября: упаковка, последовательности, королевская башня

Обнаружена ошибка упаковки первой версии поиска: замена импорта по точной строке пропустила вариант с пробелом `rollout, rank`. Локальный запуск из полной репы ошибку скрывал. Генератор теперь заменяет AST-узел импорта и проверяет его наличие; тестируются оба вида поиска. Подготовлен отдельный пакет `_v2`, сохранив первый. Его79 вариантов действительно выполнены в замороженной копии проекта без модуля-помощника. Новая отправка разрешена только после подтверждённого терминального ERROR версии1; сетевой тайм-аут не считается ошибкой задачи.

`build_safe_bank_sequences.py` выбирает среди защиты без урона сначала минимальную стоимость, затем самое позднее проверенное время. Это явно заданная демонстрационная эвристика, не утверждение оптимальности WAIT. Проверяется полный исход и легальность каждого кадра через общий `replay_match` actual PPO observation/mask. Один пример воспроизвёл12WAIT+1Cannon. Полный сбор требует все36контекстов, проверенные SHA, исходники и целые seed; данные ещё не готовы для полноценного обучения без срочных/смешанных контролей.

Отдельно воспроизведена дыра текущего штрафа: Fireball9,1 в пустом поле снимает206HP целому спящему королю, будит его и получает `empty_spell_elixir=0`. [Точный результат](defense_plan/crown_only_spell_reward_hole_20261030.json). Старый штраф проверяет наличие любого контакта, а не полезность хода.

Добавлены `sim/spell_economy.py` и отдельная опциональная среда `sim/continuous_spell_economy.py`. Они различают пустой спел, нелетальный урон только башням, попадание только по королю, спавшему при запросе, добивание башни и контакт с юнитами. У двух новых штрафов непересекающиеся категории; пока оба по умолчанию0. Добивание/контакт с юнитами не штрафуется этим новым механизмом. Сон проверен при запросе: причинность пробуждения именно этим спелом не утверждается. Боевая физика и стандартная фабрика обучения не изменены; новую среду ещё нужно включить в отдельный закреплённый пилот с проверкой exact resume.

План малого сравнения после готовности смешанного учителя: контроль, только штраф бесполезного удара по спящему королю, умеренный штраф другого нелетального crown-only расхода, демонстрации накопления с удержанием навыка. Не выбирать коэффициент по частоте карт: отдельно проверить добивание, мультицель, запас, пропущенную защиту, все6семейств и весь матч. Чип по башне иногда полезен, поэтому это абляция, а не глобальный запрет.
