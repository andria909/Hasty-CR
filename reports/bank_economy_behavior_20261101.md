# Накопление во время угрозы

Пересчитаны 144 локальных симуляционных эпизода: три прежние модели, 12 сцен, две задержки, с одной начальной атакой и с дополнительной оплаченной атакой по противоположной линии. Группа 354 уже использовалась для диагностики; это не независимый test и не игровой винрейт.

При задержке 1350 мс:

| Модель | Сценарий | Время с доступным эликсиром <4 | То же, пока есть враг | Пустые спеллы, эликсир / эпизод | Потери регенерации при полном банке / эпизод |
|---|---|---:|---:|---:|---:|
| balanced | Одна атака | 99,7% | 99,1% | 3,50 | 0,16 |
| v25 | Одна атака | 99,6% | 99,1% | 6,83 | 0,16 |
| прежний BC | Одна атака | 25,8% | 83,4% | 1,67 | 9,85 |
| balanced | Вторая атака по другой линии | 99,7% | 99,3% | 3,33 | 0,16 |
| v25 | Вторая атака по другой линии | 99,6% | 99,3% | 6,33 | 0,16 |
| прежний BC | Вторая атака по другой линии | 39,6% | 87,3% | 1,67 | 6,26 |

У BC большую часть потерь регенерации даёт время без живых врагов: при угрозе переполнение в среднем только 0,16 эликсира. В этих коротких сценариях атаки ограничены, поэтому простой после защиты сам по себе не доказывает ошибку полной стратегии. Но общий средний банк явно не подтверждает достаточный резерв **во время защиты**.

Доступный эликсир учитывает очередь ещё не исполненных команд. Доли времени измеряются на каждом 50-мс шаге, а не по числу действий. Пустой спелл определяется по завершённому попаданию без контактов; незавершённые заклинания считаются отдельно. Урон башням и команды во всех 144 эпизодах полностью совпали с прежним измерением: добавление учёта не изменило физику или решения.

Вывод для отбора: оценивать одновременно потери башен, запас во время угрозы, потери регенерации и подтверждённо пустые спеллы. Низкий банк во время полезной защиты не должен автоматически получать штраф — важен результат потраченного эликсира.

Источники: [одна атака](defense_plan/support_economy_20261101.json), [вторая атака](defense_plan/support_opposite_economy_20261101.json). В каждом отчёте закреплён снимок исходного драйвера. Для новых весов подготовлен `scripts/attack/evaluate_verified_bank_behavior.py`: все восемь проверенных кандидатов серии получают одинаковые 384 эпизода до последующего полного validation.
