# Продолжение прерванного PPO с прежним бюджетом

`scripts/kaggle/resume_full_boundary.py` продолжает один сохранённый запуск в исходном распакованном проекте. Он сверяет SHA входных файлов, config с checkpoint, исходные коэффициенты и расписание оценок, fingerprint тренера/симулятора, границу metrics и целевой бюджет. Для рабочего CUDA-режима требуется прежний бюджет 4 096 000 шагов. Технический CPU-режим ограничен 1024 шагами и не допускает отправку задания.

При продолжении меняются только вход на `--resume` и выходная папка; разрешён новый ограниченный срок сессии. Счётчик целевых шагов не обнуляется. Исходный лог остаётся отдельно, новый сегмент сохраняется отдельно, объединённый лог содержит последовательные updates без повторов. Исторический лучший checkpoint сохраняется кандидатом для итогового выбора с прежним приоритетом порога семейств.

Если второй запуск уже достиг цели, его результаты копируются с проверкой, процесс optimizer не запускается. Ошибка процесса или неполный бюджет не превращаются в успех.

## Проверено фактическим исполнением

Закреплённая команда `policy_choice/control`, CPU, бюджет 32 шага, настоящая validation после каждого из двух updates:

| Проверка | Результат |
|---|---|
| Непрерывное обучение и остановка после 16 с продолжением до 32 | Веса и всё состояние совпали точно |
| Validation | 48 фактически подсчитанных матчей; объединённые оценки совпали с непрерывными |
| Сохранённый лучший checkpoint | Итоговый выбор совпал |
| Уже завершённый запуск | 0 новых шагов, optimizer не запускался |
| Исходные файлы | SHA сохранились |
| Проверки восстановления и смежного pipeline | 47 прошли |

Отдельная проверка на заданных оценках подтверждает, что прежний checkpoint с пройденным порогом сохраняет приоритет над новым с большим баллом, но проваленным порогом.

[Машинный отчёт](defense_plan/full_boundary_adapter_preflight_20261104.json). Артефакты: `tmp/full_boundary_adapter_preflight_20261104_v2/`. Первый проход сохранён отдельно.

Это исполняемый адаптер отдельного запуска, а не готовая автоматическая повторная отправка пары в Kaggle. Для удалённого восстановления ещё нужны упаковка исходных закреплённых проектов и собранных артефактов, проверка происхождения всей пары и итоговый удалённый сбор. CUDA-resume этим CPU-испытанием не доказан. Сейчас пилоты продолжают исходные запуски; новых GPU-задач этот код не создавал.
