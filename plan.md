 - Эти упражнения реализовать отдельным атакующим режимом. Переход к его обучению — после приёмки защитной модели, как указано ниже; не подменять ими текущее защитное обучение.

 - Для каждой цели задавать ограниченное окно выполнения. Если модель долго ничего полезного не делает, упускает возможность выпустить хога/добить башню или расходует карты без результата, окно истекает и эпизод заканчивается с отдельным результатом «цель не выполнена за отведённое время». Не прекращать эпизод по субъективной оценке «плохого действия».
 - Длительность окна выбирать случайно для каждого эпизода, с учётом типа упражнения, расстояния, доступного эликсира, задержки выставления и времени полёта заклинания. Цель должна быть физически достижима; диапазоны сначала проверить на простых эталонных действиях и затем подбирать по validation.
 - Не использовать один фиксированный дедлайн: модель иначе вычислит остаток по времени с начала эпизода. Скрытый дедлайн не должен попадать в observation, признаки сценария, ID, action mask или подсказку награды до завершения.
 - В части эпизодов скрывать точный остаток времени и сигнал «осталось мало»: модель должна сама своевременно использовать возможность атаки. В другой части явно давать остаток окна и признак доступности таймера, чтобы она училась действовать при известной срочности. Соотношение режимов подбирать по validation; в отчётах оценивать их отдельно.
 - Скрытие учебного дедлайна отделить от обычных игровых часов и режима эликсира. Если обычные часы остаются доступны, случайный учебный дедлайн не должен однозначно вычисляться из них. Видимый учебный таймер обозначать как отдельный признак; отсутствие таймера не кодировать нулём, означающим «время вышло».
 - Варьировать HP башен, обе линии, стартовую руку/цикл, запас эликсира, наличие здания/защитников, уже идущую поддержку и момент появления возможности атаки. Перемешивать соло-хога, поддержку пуша, предикт здания и добивание заклинанием; не проходить их неизменно от простого к сложному.
 - Не считать отсутствие урона в каждый отдельный момент бездействием: путь хога, ожидание эликсира, размен поддержки, кайтинг и полёт уже выпущенного заклинания могут быть правильной частью решения. Срыв окна фиксировать по невыполненной цели к дедлайну, а не по короткой паузе в нанесении урона.
 - Для добивания учитывать фактический урон по коронной башне, достаточный бюджет и уже летящие свои заклинания. Не поощрять повторный Fireball/Zap в башню, которую уже гарантированно добьёт выпущенный снаряд.
 - Разделять достижение цели, смерть любого короля, пропуск учебного окна и общий технический таймаут. Смерть короля остаётся немедленным терминальным событием. Учебный дедлайн — часть задачи со своим результатом и наградой; не смешивать его с техническим обрывом и правилами bootstrap в RL.
 - Для атакующего режима отдельно определить завершение после выполнения/срыва цели. Правило защитного режима «после гибели последнего атакующего врага больше не выставлять карты» не должно запрещать соло-атаку на башни при отсутствии вражеских войск.
 - Награждать выполнение цели, полезный урон и экономию эликсира; учитывать пропущенную возможность/неуспех окна. Конкретные коэффициенты и диапазоны времени подбирать только по validation. Непрерывное откладывание действий и бесконечное продление эпизода не должны давать выигрышную награду.
 - Метрики: доля выполненных целей, время от появления возможности до выпуска хога/заклинания, фактический урон хога по целевой башне, успешные добивания, лишние заклинания, потраченный эликсир и доля пропущенных окон. Показывать отдельно по типу пуша, сложности, линии, шафлу и видимости таймера.
