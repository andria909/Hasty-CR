 - Не считать отсутствие урона в каждый отдельный момент бездействием: путь хога, ожидание эликсира, размен поддержки, кайтинг и полёт уже выпущенного заклинания могут быть правильной частью решения. Срыв окна фиксировать по невыполненной цели к дедлайну, а не по короткой паузе в нанесении урона.
 - Для добивания учитывать фактический урон по коронной башне, достаточный бюджет и уже летящие свои заклинания. Не поощрять повторный Fireball/Zap в башню, которую уже гарантированно добьёт выпущенный снаряд.
 - Разделять достижение цели, смерть любого короля, пропуск учебного окна и общий технический таймаут. Смерть короля остаётся немедленным терминальным событием. Учебный дедлайн — часть задачи со своим результатом и наградой; не смешивать его с техническим обрывом и правилами bootstrap в RL.
 - Для атакующего режима отдельно определить завершение после выполнения/срыва цели. Правило защитного режима «после гибели последнего атакующего врага больше не выставлять карты» не должно запрещать соло-атаку на башни при отсутствии вражеских войск.
 - Награждать выполнение цели, полезный урон и экономию эликсира; учитывать пропущенную возможность/неуспех окна. Конкретные коэффициенты и диапазоны времени подбирать только по validation. Непрерывное откладывание действий и бесконечное продление эпизода не должны давать выигрышную награду.
 - Метрики: доля выполненных целей, время от появления возможности до выпуска хога/заклинания, фактический урон хога по целевой башне, успешные добивания, лишние заклинания, потраченный эликсир и доля пропущенных окон. Показывать отдельно по типу пуша, сложности, линии, шафлу и видимости таймера.
 - Для PPO/GRPO сохранять одинаковые цели, начальные состояния, скрытые дедлайны и маски видимости при парном сравнении. Родственные варианты пуша держать в одном split; test не использовать для выбора длительности окна, наград или лучшего чекпойнта.
